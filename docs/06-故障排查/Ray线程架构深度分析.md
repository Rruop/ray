  7.2 架构设计要点                                                                                                                                                                                                                                                      
                                                                                                                                                                                                                                                                        
  1. 事件驱动设计: 所有 Ray 进程使用 Boost.Asio io_context 进行异步事件处理，工作在线程间通过 post() 传递。                                                                                                                                                             
  2. 线程隔离: GCS 中的关键子系统（PubSub、TaskManager、RaySyncer）拥有专用 IO Context/线程，避免相互阻塞。                                                                                                                                                             
  3. gRPC 线程模型: 服务器和客户端都使用独立的轮询线程从 CompletionQueue 读取事件，然后将回调 post 到主事件循环。                                                                                                                                                       
  4. Plasma Store 线程: 在 Raylet 进程内运行独立的 store.io 线程，独立处理对象存储操作。                                                                                                                                                                                
  5. Object Manager 线程池: 使用可配置的线程池 (rpc.obj.mgr.{N}) 处理对象传输 RPC，数据拷贝操作在这些线程上进行。
