## 需求背景

在 Ray Data 的 map 操作（如 `map_batches`）中，当 row 数据的某个字段超过指定阈值时，希望将该数据放入 object store，用返回的 ObjectRef 替换原始数据，传递给下游算子，以减少内存压力。

### 设计目标

```python
def process_batch(batch):
    # 将大数据放入 object store，返回 ObjectRef
    batch["data"] = [put_if_large(item, threshold_bytes=100*1024)
                     for item in batch["data"]]
    return batch

def consume_batch(batch):
    # 从 ObjectRef 获取实际数据
    batch["data"] = [get_if_ref(item) for item in batch["data"]]
    return batch
```

## ObjectRef 序列化机制

### 两种序列化模式

Ray 中 ObjectRef 的序列化分为两种模式：

| 模式 | 触发条件 | 行为 | 生命周期管理 |
|------|----------|------|--------------|
| **带内序列化** (In-band) | `ray.put()` 内部 | ObjectRef 被收集到 `contained_object_refs` | ✅ 正确追踪，随外层对象释放 |
| **带外序列化** (Out-of-band) | 直接 `pickle.dumps()` | ObjectRef 被永久 pin | ❌ Worker 进程结束才释放 |

### 带内序列化流程

```python
# python/ray/_private/serialization.py

def _serialize_to_pickle5(self, metadata, value):
    try:
        self.set_in_band_serialization()  # 设置带内标志
        inband = pickle.dumps(value, protocol=5, ...)
    finally:
        self.set_out_of_band_serialization()

    # contained_object_refs 被收集并传递给 C++ 层
    return Pickle5SerializedObject(
        metadata, inband, writer,
        self.get_and_clear_contained_object_refs()
    )
```

当 `ray.put()` 序列化一个包含 ObjectRef 的对象时：
1. 设置 `in_band = True` 标志
2. 序列化过程中遇到的 ObjectRef 被收集到 `contained_object_refs`
3. 这些 refs 被传递给 C++ 层的 `CreateOwnedAndIncrementLocalRef`
4. C++ 层建立正确的引用关系：外层对象存在时，内部对象不会被删除

### 带外序列化流程

```python
# python/ray/_private/serialization.py:302-335

def add_contained_object_ref(self, object_ref, ...):
    if self.is_in_band_serialization():
        # 带内：正确追踪引用
        self._thread_local.object_refs.add(object_ref)
    else:
        # 带外：永久 pin 对象！
        ray._private.worker.global_worker.core_worker.add_object_ref_reference(
            object_ref
        )
```

当直接使用 `pickle.dumps()` 序列化 ObjectRef 时（如 Arrow 扩展类型中）：
1. `in_band` 标志为 False
2. ObjectRef 通过 `add_object_ref_reference` 被永久 pin
3. 对象在 Worker 进程生命周期内不会被 GC

### Ray Data 中的问题

Ray Data 使用 `ArrowPythonObjectArray` 存储 Python 对象：

```python
# python/ray/data/_internal/object_extensions/arrow.py

class ArrowPythonObjectArray(pa.ExtensionArray):
    def from_objects(objects):
        for obj in objects:
            # 这里使用 pickle_dumps，是带外序列化！
            dumped_bytes = pickle_dumps(obj, "Error pickling...")
```

**问题**：`pickle_dumps` 是带外序列化，ObjectRef 会被永久 pin。

## Worker 与 Task 的关系

### 架构概览

```
┌─────────────────────────────────────────────────────────────┐
│                      Ray Cluster                             │
├─────────────────────────────────────────────────────────────┤
│  Node 1                          Node 2                      │
│  ┌──────────────────┐           ┌──────────────────┐        │
│  │ Worker Process 1 │           │ Worker Process 3 │        │
│  │  ┌─────────────┐ │           │  ┌─────────────┐ │        │
│  │  │   Task A    │ │           │  │   Task D    │ │        │
│  │  └─────────────┘ │           │  └─────────────┘ │        │
│  │  ┌─────────────┐ │           │  ┌─────────────┐ │        │
│  │  │   Task B    │ │ (串行执行) │  │   Task E    │ │        │
│  │  └─────────────┘ │           │  └─────────────┘ │        │
│  └──────────────────┘           └──────────────────┘        │
│  ┌──────────────────┐                                       │
│  │ Worker Process 2 │                                       │

```

### 核心概念

| 概念 | 说明 | 生命周期 |
|------|------|----------|
| **Worker 进程** | Python 进程，负责执行 Task | 长期存活，可复用执行多个 Task |
| **Task** | 一次远程函数调用 | 短暂，执行完就结束 |
| **Actor** | 有状态的 Worker | 与 Actor 实例同生命周期 |

### Ray Data 中的执行模式

```python
# Task 模式（默认）：Worker 可复用
ds.map_batches(process_fn)  # 每个 batch 是一个 Task

# Actor 模式：专用 Worker
ds.map_batches(ProcessorClass, compute=ray.data.ActorPoolStrategy(size=4))
```

## 内存泄漏问题分析

### 问题场景

```
时间线:
────────────────────────────────────────────────────────────────►

Worker Process 1 (长期存活)
│
├── Task 1: put_if_large() 创建 ObjectRef_A
│            ↓
│            ObjectRef_A 被序列化到 Arrow (带外序列化)
│            ↓
│            add_object_ref_reference(ObjectRef_A) → 永久 pin!
│
├── Task 2: put_if_large() 创建 ObjectRef_B
│            ↓
│            add_object_ref_reference(ObjectRef_B) → 永久 pin!
│
├── Task 3: ... ObjectRef_C 永久 pin!
│
├── Task 4: ... ObjectRef_D 永久 pin!
│
│   ... 内存持续增长 ...
│
└── Worker 进程结束时才释放所有 pin 的对象
```

### 内存影响估算

```python
# 假设场景
# - 每个 batch 有 100 条数据
# - 每条大数据 1MB
# - 处理 10000 个 batch

# 如果一个 Worker 处理了 1000 个 batch
# 每个 batch 产生 10 个大数据 ObjectRef

累计 pin 的数据量 = 1000 × 10 × 1MB = 10GB  # 不会释放！
```

### 为什么 Task 结束不能释放？

```python
# 带外序列化时，引用被添加到 Worker 级别的 core_worker
ray._private.worker.global_worker.core_worker.add_object_ref_reference(object_ref)

# global_worker 是进程级别的单例
# 只有进程结束才会清理
```

### 正常 vs 问题场景对比

```python
# 正常情况（不经过 Arrow 序列化）
def normal_task():
    ref = ray.put(large_data)  # 创建 ObjectRef
    result = ray.get(ref)       # 使用
    return result
    # Task 结束，ref 变量被 GC
    # ObjectRef.__dealloc__ 被调用
    # remove_object_ref_reference() 移除引用
    # ✅ 对象可以被回收

# 问题情况（经过 Arrow 序列化）
def problem_task():
    ref = ray.put(large_data)
    return {"data": ref}  # 返回 ObjectRef
    # Arrow 序列化时调用 pickle_dumps(ref)
    # add_object_ref_reference(ref) 被调用 - 永久 pin
    # ❌ 即使 task 结束，ref 仍然被 pin
```

## 解决方案

### 为什么不能简单使用带内序列化？

```
ArrowPythonObjectArray.from_objects()          ray.put(arrow_table)
         ↓                                              ↓
   pickle_dumps(ObjectRef)                       序列化 Arrow Table
         ↓                                              ↓
   ObjectRef 被收集？                            contained_object_refs
         ↓                                       需要传递到 C++ 层
   即使设置了 in_band 标志                               ↓
   这些 refs 也无法传递给                         但这两步是分离的！
   后续的 ray.put()                              无法关联
```

**核心问题**：Arrow 扩展类型的序列化和最终的 `ray.put()` 是两个独立的步骤，中间没有机制传递 `contained_object_refs`。

### 为什么不能只存储 ref_binary？

一个简单的想法是只存储 ObjectRef 的二进制表示，在需要时重建：

```python
# 错误的方案
class ObjectRefHandle:
    def __init__(self, ref):
        self.ref_binary = ref.binary()
        self.owner_address = ref.owner_address()
        # 原始 ref 可能被 GC！

    def get(self):
        ref = ObjectRef(self.ref_binary, self.owner_address)
        return ray.get(ref)  # 可能失败！对象已被删除
```

**问题**：如果原始 ObjectRef 被 GC，底层数据可能被删除，导致后续获取失败。

### 方案对比

| 方案 | 实现 | 优点 | 缺点 |
|------|------|------|------|
| **原始方案** (`put_if_large`) | 直接返回 ObjectRef | 简单 | ⚠️ 内存泄漏 |
| **安全方案** (`put_if_large_safe`) | 返回 ObjectRefHandle + Actor Registry | ✅ 可控的生命周期 | 需要 Actor |

## Actor Registry 设计

### 核心思路

使用一个集中的 Actor 来持有所有 ObjectRef，防止被 GC：

```
┌─────────────────────────────────────────────────────────────┐
│                    Ray Cluster                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │         _ObjectRefRegistryActor (Detached)           │   │
│  │                                                       │   │
│  │   _registry = {                                       │   │
│  │       "abc123...": ObjectRef_A,  ← 持有引用防止 GC   │   │
│  │       "def456...": ObjectRef_B,                       │   │
│  │       "ghi789...": ObjectRef_C,                       │   │
│  │   }                                                   │   │
│  └─────────────────────────────────────────────────────┘   │
│           ↑                    ↑                            │
│           │                    │                            │
│  ┌────────┴───────┐   ┌───────┴────────┐                   │
│  │   Worker 1      │   │    Worker 2    │                   │
│  │                 │   │                │                   │
│  │ ObjectRefHandle │   │ ObjectRefHandle│                   │
│  │ (只有 bytes)    │   │ (只有 bytes)   │                   │
│  └─────────────────┘   └────────────────┘                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Actor 实现

```python
@ray.remote
class _ObjectRefRegistryActor:
    """分布式 ObjectRef 注册表 Actor"""

    def __init__(self):
        self._registry: Dict[str, ObjectRef] = {}

    def put(self, handle_id: str, ref: ObjectRef) -> None:
        """存储 ObjectRef，防止被 GC"""
        self._registry[handle_id] = ref

    def release(self, handle_id: str) -> bool:
        """释放 ObjectRef，允许被 GC"""
        if handle_id in self._registry:
            del self._registry[handle_id]
            return True
        return False

    def release_all(self) -> int:
        """释放所有 ObjectRef"""
        count = len(self._registry)
        self._registry.clear()
        return count
```

### Actor 特性

| 特性 | 值 | 说明 |
|------|-----|------|
| `name` | `"_object_ref_registry"` | 固定名称，任何 Worker 可获取 |
| `lifetime` | `"detached"` | 脱离创建者，持续存在直到显式 kill |
| `namespace` | `"ray_data"` | 避免与用户 Actor 冲突 |
| `num_cpus` | `0` | 不占用 CPU 资源 |

### ObjectRefHandle 设计

```python
class ObjectRefHandle:
    __slots__ = ("handle_id", "ref_binary", "owner_address")

    # 只存储基本类型，避免触发 ObjectRef 序列化
    # - handle_id: str (ObjectRef 的 hex)
    # - ref_binary: bytes (ObjectRef 的二进制表示)
    # - owner_address: str (所有者地址)
```

### 完整工作流程

```
创建 Handle (Worker 1):
─────────────────────────────────────────────────────────────
1. ray.put(data) → ObjectRef
2. 获取 ref_binary, owner_address
3. registry.put(handle_id, ref)  ← Actor 持有引用
4. 返回 ObjectRefHandle(只有 bytes)
5. Arrow 序列化时只序列化 bytes，不触发 ObjectRef 序列化！


跨 Worker 传递:
─────────────────────────────────────────────────────────────
ObjectRefHandle 被序列化 → 只有 str 和 bytes
                  ↓
           传递到 Worker 2
                  ↓
ObjectRefHandle 被反序列化 → 还是 str 和 bytes


使用 Handle (Worker 2):
─────────────────────────────────────────────────────────────
1. ObjectRef(ref_binary, owner_address)  # 重建 ObjectRef
2. ray.get(ref)  # 获取数据（对象还在，因为 Actor 持有引用）


释放 Handle:
─────────────────────────────────────────────────────────────
1. registry.release(handle_id)  # Actor 释放引用
2. 如果没有其他引用 → 对象可被 GC
```

### 生命周期保证

```
┌─────────────────────────────────────────────────────────────┐
│                    数据生命周期                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  ray.put(data)                                              │
│       ↓                                                     │
│  ObjectRef 创建，数据存入 Object Store                       │
│       ↓                                                     │
│  ObjectRefHandle.from_ref(ref)                              │
│       ↓                                                     │
│  registry.put(handle_id, ref)  ← Actor 持有引用             │
│       ↓                                                     │
│  原始 ObjectRef 在 Worker 1 被 GC？                         │
│       ↓                                                     │
│  没关系！Actor 仍持有引用，数据不会被删除                    │
│       ↓                                                     │
│  Worker 2 调用 handle.get()                                 │
│       ↓                                                     │
│  重建 ObjectRef，获取数据 ✅                                 │
│       ↓                                                     │
│  handle.release() 或 ObjectRefHandle.release_all()          │
│       ↓                                                     │
│  Actor 释放引用，数据可被 GC                                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## API 参考

### 安全版本（推荐）

#### `put_if_large_safe(data, threshold_bytes=100*1024)`

安全地将大数据放入 object store。

```python
def put_if_large_safe(
    data: Any,
    threshold_bytes: int = 100 * 1024
) -> Union[Any, ObjectRefHandle]:
    """
    Args:
        data: 要检查的数据
        threshold_bytes: 大小阈值（字节），默认 100KB

    Returns:
        如果数据超过阈值，返回 ObjectRefHandle；否则返回原始数据

```

从 ObjectRefHandle 获取数据。

```python
def get_if_handle(data: Union[Any, ObjectRefHandle]) -> Any:
    """
    Args:
        data: ObjectRefHandle 或普通数据

    Returns:
        实际数据
    """
```

#### `batch_put_if_large_safe(batch, columns, threshold_bytes)`

批量处理 batch 中的指定列。

```python
def batch_put_if_large_safe(
    batch: Dict[str, List[Any]],
    columns: Optional[List[str]] = None,
    threshold_bytes: int = 100 * 1024,

```

#### `batch_get_if_handle(batch, columns, release=False)`

批量从 ObjectRefHandle 获取数据。

```python
def batch_get_if_handle(
    batch: Dict[str, List[Any]],
    columns: Optional[List[str]] = None,
    release: bool = False,  # 是否在获取后释放 handle
) -> Dict[str, List[Any]]:
```

#### `cleanup_registry_actor()`

清理所有 handle 并销毁 registry actor。

```python
def cleanup_registry_actor() -> int:
    """
    清理所有 ObjectRefHandle 并销毁 registry actor。
    在完成所有数据处理后调用。

    Returns:
        释放的 handle 数量
    """
```

#### `ObjectRefHandle` 类

```python
class ObjectRefHandle:
    handle_id: str      # ObjectRef 的 hex 表示
    ref_binary: bytes   # ObjectRef 的二进制表示
    owner_address: str  # 所有者地址

    @classmethod
    def create(cls, data: Any) -> "ObjectRefHandle":
        """创建 handle，将数据放入 object store 并注册到 Actor"""

    @classmethod
    def from_ref(cls, ref: ObjectRef) -> "ObjectRefHandle":
        """从已有的 ObjectRef 创建 handle 并注册到 Actor"""

    def get(self) -> Any:
        """获取数据"""

    def get_ref(self) -> ObjectRef:
        """重建并获取 ObjectRef"""

    def release(self) -> bool:
        """释放此 handle，允许对象被 GC"""

    @staticmethod
    def release_many(handles: List["ObjectRefHandle"]) -> int:
        """批量释放多个 handle（更高效）"""

    @staticmethod
    def release_all() -> int:
        """释放所有 handle"""

    @staticmethod
    def registry_size() -> int:
        """获取 registry 中的 handle 数量"""
```

## 使用示例

### 安全版本用法（推荐）

```python
import ray
from ray.data import (
    put_if_large_safe,
    get_if_handle,
    batch_put_if_large_safe,
    batch_get_if_handle,
    ObjectRefHandle,
    cleanup_registry_actor,
)

ray.init()

# 创建包含大数据的 dataset
large_arrays = [bytes(200 * 1024) for _ in range(100)]
ds = ray.data.from_items([{"data": arr, "label": i} for i, arr in enumerate(large_arrays)])

# 方式 1：单个元素处理
def process_batch(batch):
    batch["data"] = [
        put_if_large_safe(item, threshold_bytes=100*1024)
        for item in batch["data"]
    ]
    return batch

def consume_batch(batch):
    batch["data"] = [get_if_handle(item) for item in batch["data"]]
    return batch

ds = ds.map_batches(process_batch)
ds = ds.map_batches(consume_batch)

# 方式 2：批量处理（推荐）
def process_batch(batch):
    return batch_put_if_large_safe(batch, columns=["data"], threshold_bytes=100*1024)

def consume_batch(batch):
    # release=True 在获取数据后自动释放 handle
    return batch_get_if_handle(batch, columns=["data"], release=True)

ds = ds.map_batches(process_batch)
ds = ds.map_batches(consume_batch)

# Pipeline 结束后清理 registry actor
cleanup_registry_actor()
```

### 手动管理生命周期

```python
# 创建 handles
handles = []
for data in large_data_list:
    handle = ObjectRefHandle.create(data)
    handles.append(handle)

# 使用 handles...
for handle in handles:
    data = handle.get()
    process(data)

# 批量释放（更高效）
released = ObjectRefHandle.release_many(handles)
print(f"Released {released} handles")

# 或者释放所有
released = ObjectRefHandle.release_all()

# 完全清理（包括销毁 Actor）
cleanup_registry_actor()
```

### 监控 Registry 状态

```python
# 检查当前 registry 大小
size = ObjectRefHandle.registry_size()
print(f"Registry contains {size} handles")

# 在长时间运行的任务中定期检查
if size > 10000:
    print("Warning: Large number of handles, consider releasing")
```

## 最佳实践

### 1. 优先使用安全版本

```python
# ✅ 推荐
from ray.data import put_if_large_safe, get_if_handle

# ⚠️ 仅用于短期 pipeline
from ray.data import put_if_large, get_if_ref
```

### 2. 在最后一个消费者中释放 Handle

```python
# 在最后一个消费者中设置 release=True
def final_consumer(batch):
    return batch_get_if_handle(batch, columns=["data"], release=True)
```

### 3. Pipeline 结束后清理

```python
# 处理完成后清理所有资源
try:
    result = ds.map_batches(process).map_batches(consume).take_all()
finally:
    cleanup_registry_actor()
```

### 4. 监控 Registry 大小

```python
# 定期检查 registry 大小
size = ObjectRefHandle.registry_size()
if size > 10000:
    print(f"Warning: {size} handles in registry")
```

### 5. 批量释放提高效率

```python
# ❌ 效率较低：逐个释放
for handle in handles:
    handle.release()

# ✅ 更高效：批量释放
ObjectRefHandle.release_many(handles)
```

### 6. 避免在长期运行的 pipeline 中使用原始版本

```python
# ❌ 长期运行的 Actor-based pipeline 不要使用原始版本
ds.map_batches(
    ProcessorWithPutIfLarge,  # 使用了 put_if_large
    compute=ray.data.ActorPoolStrategy(size=4)
)  # Actor 长期存活，内存会持续增长

# ✅ 使用安全版本
ds.map_batches(
    ProcessorWithPutIfLargeSafe,  # 使用 put_if_large_safe
    compute=ray.data.ActorPoolStrategy(size=4)
)
```

## 注意事项

### Registry Actor 的生命周期

1. **自动创建**：首次调用 `put_if_large_safe` 或 `ObjectRefHandle.create` 时自动创建
2. **跨 Worker 共享**：所有 Worker 共享同一个 registry actor
3. **需要手动清理**：使用 `cleanup_registry_actor()` 清理

### 性能考虑

1. **Actor 调用开销**：每次创建 handle 需要一次 Actor 调用
2. **批量操作**：使用 `release_many` 比逐个 `release` 更高效
3. **适用场景**：适用于大数据传递，不适用于小数据的高频操作

### 错误处理

```python
try:
    handle = ObjectRefHandle.create(data)
    result = handle.get()
except Exception as e:
    # 确保清理
    handle.release()
    raise
```
